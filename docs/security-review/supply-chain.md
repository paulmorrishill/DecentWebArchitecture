# Supply chain checklists

Three lists for the path from source to running system: **SLSA v1.2** (approved November 2025; Build track L1–L3 and the new Source track L1–L4), the **OpenSSF Scorecard checks** (Scorecard v5.6.0, October 2026, 20 checks), and the **NIST Secure Software Development Framework, SP 800-218 v1.1** (February 2022, still the final edition; v1.2, SP 800-218 Rev. 1, is an initial public draft from December 2025). They are the current ones as of November 2026. How to run the review is [33-security-review](../33-security-review.md).

[28-supply-chain-and-build-inputs](../28-supply-chain-and-build-inputs.md) controls what goes **into** a build. These lists also ask what comes **out**: proof of which source and which pipeline made the artifact, and proof that the source itself was protected. Expect gaps there.

- **Repo rule.** ✅ a rule here, if followed, meets the item. 🟡 a rule meets part of it. ❌ no rule. ➖ the architecture as written has no such surface. 🏢 an organisational, people or physical control that an architecture cannot cover. **A tick is not a pass.** It says where to look; the reviewer still checks.
- **Tracker.** [supply-chain.csv](supply-chain.csv) has every row of every list below, with empty result columns.
- **Wording.** Items are paraphrased; the SLSA specification, the Scorecard check documentation and NIST SP 800-218 are the authority. Only their identifiers and titles are used here.
- **Not yet final:** SSDF v1.2. When NIST publishes it as final, map it again; do not edit the v1.1 rows to fit ([33](../33-security-review.md) § 8).

## What a SaaS team gets wrong

- **Pinning the inputs is not attesting the output.** [28](../28-supply-chain-and-build-inputs.md) scores well on Pinned-Dependencies and on most of A03:2025, and still reaches no SLSA Build level: Build L1 needs a provenance document for each artifact, and there is none.
- **A SaaS team is its own consumer of provenance.** Nobody downloads the API bundle, so "distribute provenance" feels pointless. The consumer is the deploy step, which should check the artifact came from this pipeline at this commit before it publishes, and the auditor who asks what ran on a date.
- **Build L3 is about the runner, not the workflow file.** The signing key must be out of reach of the build steps, and each build must run in a fresh environment. A self-hosted runner that keeps its workspace between jobs fails "isolated" however well it is cleaned ([32](../32-mobile-delivery.md) § 4.2).
- **An agent and its owner are one person.** An agent that pushes with the owner's account, and the owner who then approves the pull request, is one identity. Two-party review (Source L4) and the Code-Review check need the git host to require a second, different approver.
- **A written branch rule is not a protected branch.** [16](../16-ci-cd.md) § 1 says the release branch moves only by merge. Source L3 and Branch-Protection ask the git host to refuse a direct push, a force-push and a deletion, and to keep refusing them continuously.
- **The pipeline token is a credential too.** [28](../28-supply-chain-and-build-inputs.md) § 7 scopes the cloud role to a branch, but the CI host's own token can still write to the repository by default. Set it to read-only and grant write per job (Token-Permissions). A workflow that runs pull-request code with that token or with secrets is the Critical Dangerous-Workflow finding.
- **Scorecard was built for public projects.** Contributors, CII-Best-Practices, License, Maintained and Packaging are signals for someone choosing an open-source dependency; mark them N/A for a private product rather than chasing them. On a private repository, run the tool yourself and keep the result internal. Branch-Protection and Webhooks need a token that can read the repository's admin settings, or they report no result, which is not a pass.
- **Keep what shipped.** [16](../16-ci-cd.md) § 7 sets a short artifact retention, which is right for cost. SSDF PS.3 still wants each release kept or reproducible: keep the digest, the provenance and the bill of materials per release, not the artifact.
